# 部署指南

本文把「在自己电脑上能玩」变成「发给朋友一个链接就能一起玩」。

---

## 一、为什么不能只用 GitHub Pages

GitHub Pages 只能托管**静态文件**（HTML / CSS / JS），它没有可以运行程序的服务器。

联机模式需要一个「中间人」：

```
玩家 A ──┐
         ├──► 你的服务端（裁决出牌、转发消息、保管所有人的手牌）
玩家 B ──┤
         └──► 没有它，两个浏览器之间无法直接通信
```

而且它必须是**唯一**的裁判。如果规则跑在玩家电脑上，任何人按 F12 改几行 JS 就能给自己发一手好牌。

所以要解决「不在同一个 WiFi 也能玩」，必须让这台 Node 服务在公网上有地址。

## 三、方案一：同一 WiFi（零成本，最稳）

如果你们在同一个家、同一个宿舍、连同一个路由器：

1. 启动服务：

   ```bash
   cd D:\AI_workspace\web_game
   npm start
   ```

2. 查你的局域网 IP：

   ```bash
   ipconfig
   ```

   找到「IPv4 地址」，形如 `192.168.1.5`。

3. 让朋友在浏览器打开 `http://192.168.1.5:3000`

**第一次运行 Windows 会弹防火墙提示，必须点「允许访问」**，否则别人连不上。如果当时点了取消，去「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」手动勾上 Node.js。

优点：零延迟、零成本、最稳定。缺点：出了这个 WiFi 就玩不了。

## 四、方案二：公网隧道（零成本，跨网络）

原理：你的电脑继续跑服务，用一个隧道工具把它「接」到公网上，得到一个临时网址。不需要注册账号、不需要服务器，也不需要重新部署。

用的是 Cloudflare 的免费快速隧道。

> ✅ **已在本机验证通过**：隧道建立后从公网访问正常，WebSocket 握手返回 101，两个独立浏览器通过该地址完成建房、加入、开局、出牌同步。首次打开页面约 9 秒（流量绕道洛杉矶节点），之后会快一些。

### 最省事的方式：双击脚本

项目根目录有 `start-public.bat`，双击它即可：自动启动服务、建立隧道、打开浏览器。隧道窗口里那行 `https://xxxx.trycloudflare.com` 就是发给朋友的链接。

前提是 `cloudflared` 已安装（见下方步骤 1），本机已装好。

### 手动方式（三行命令）

如果脚本出问题，就手动开三个终端窗口。

**步骤 1：安装（只需一次）**

```bash
winget install --id Cloudflare.cloudflared
```

装完**关掉终端重新开一个**（让新命令生效）。

**步骤 2：启动游戏服务**

```bash
cd D:\AI_workspace\web_game
npm start
```

这个窗口要一直开着，关掉游戏就没了。

**步骤 3：开隧道**

```bash
cloudflared tunnel --url http://localhost:3000
```

稍等几秒，屏幕上会出现：

```
https://随机单词-随机单词-随机单词.trycloudflare.com
```

**这个地址就是发给朋友的链接**，已经是 HTTPS，手机电脑都能开。

### 玩完怎么关

在两个窗口各按一次 `Ctrl + C`，地址立即失效。

### 必须知道的三个限制

1. **地址每次都不一样**。每开一次隧道就是一个新网址，得重新发给朋友。
2. **你的电脑不能关、不能睡眠**。合上笔记本就断了。
3. **速度取决于你家宽带上行**，而且免费隧道会绕道海外节点，延迟通常在 1–2 秒。2–4 人回合制游戏够用，但不如局域网流畅。

如果想固定域名、长期可用，得注册 Cloudflare 账号并绑一个自己的域名（免费），那是另一套配置。

## 五、方案三：Railway（长期在线，约 $5/月）

想让链接一直有效、不依赖你的电脑开着，就用这个。仓库里的 `Dockerfile` 可以直接用。

### 步骤 1：注册

1. 打开 <https://railway.app>
2. 点 **Login** → 选 **GitHub**，用你的 `tunbao666` 账号授权
3. 按提示完成验证（可能要求绑定支付方式）

### 步骤 2：部署

1. 点 **New Project** → **Deploy from GitHub repo**
2. 选 **Uno-game** 仓库
3. Railway 会自动检测到 `Dockerfile`，直接开始构建
4. 等 2–3 分钟，状态变成 **Success**

### 步骤 3：生成网址

1. 点进这个服务 → **Settings** → **Networking**
2. 找到 **Public Networking**，点 **Generate Domain**
3. 得到一个形如 `uno-game-production-xxxx.up.railway.app` 的地址

**这就是发给朋友的链接。**

### 步骤 4：验证

```bash
curl https://你的地址.up.railway.app/healthz
# 期望：{"status":"ok","rooms":0,"uptime":123}
```

然后用手机流量（关掉 WiFi）打开链接，建个房间试试。

### 关于费用

Railway 按实际用量计费，一个 512MB 的小服务常驻大约每月 $5 以内。用它的 **Hobby** 计划即可。不想花钱时可以在面板里 **Pause** 服务，暂停期间不计费。

### 以后更新代码

Railway 默认开启自动部署，本地 `git push` 后会自动重新构建。

## 六、附录：用 Docker 部署到任何地方

`Dockerfile` 是通用的，Fly.io、Koyeb、自己的 VPS 都能用：

```bash
docker build -t uno-game .
docker run -p 3000:3000 uno-game
```

放到服务器上时，唯一要注意的是**反向代理必须转发 WebSocket**。Nginx 示例：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;   # WebSocket 是长连接，别让它 60 秒就断
}
```

漏掉 `Upgrade` 和 `Connection` 这两行，现象是「页面能打开，但点创建房间一直转圈」——WebSocket 握手被降级成了普通 HTTP。

如果你以后能稳定访问 Render，仓库里的 `render.yaml` 仍然可用：Dashboard → **New +** → **Blueprint** → 选仓库 → **Apply**。

## 七、排查清单

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 页面能开，点创建房间一直转 | WebSocket 被代理拦了 | 检查反向代理的 `Upgrade` / `Connection` 头 |
| 朋友打不开局域网地址 | 防火墙拦了 3000 端口 | 允许 Node.js 通过防火墙 |
| 隧道地址打开是 Cloudflare 错误页 | 本地服务没启动 | 确认 `npm start` 那个窗口还开着 |
| 显示「房间不存在」 | 服务重启过，房间数据在内存里已清空 | 重新建房 |
| 显示「服务器房间已满」 | 达到 200 房间上限 | 极少发生，等几分钟空房自动回收 |
| 显示「这局已经开始了」 | 对局中途有人想加入 | 设计如此，等这局结束 |
| 手机连不上，电脑可以 | 手机连的是别的网络 | 检查是否同一 WiFi / 用公网地址 |

自检服务是否活着：

```bash
curl https://你的地址/healthz
# 期望：{"status":"ok","rooms":0,"uptime":123}
```

## 八、安全提醒

- 链接公开，任何人拿到都能建房。房间码是 4 位数字，理论上存在被陌生人撞码进入的可能——休闲游戏，影响仅限于「有人乱入」，介意就打完把房间关掉。
- 昵称做了转义和长度限制，不能注入 HTML。
- 服务端是唯一持有全部手牌的一方。下发的数据里别人的手牌只有张数，摸牌堆只有剩余数量，随机种子不下发。改前端看不到任何隐藏信息。
- 房间数据只存在内存里，进程重启即清空，不会残留任何玩家信息。
