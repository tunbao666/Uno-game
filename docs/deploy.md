# 部署指南

本文把「在本地能玩」变成「发给朋友一个链接就能一起玩」。

---

## 一、先理解一件事：为什么不能只用 GitHub Pages

GitHub Pages 只能托管**静态文件**（HTML / CSS / JS），它没有可以运行程序的服务器。

这个游戏的联机模式需要一个「中间人」：

```
玩家 A ──┐
         ├──► 你的服务端（裁决出牌、转发消息、保管所有人的手牌）
玩家 B ──┤
         └──► 没有它，两个浏览器之间无法直接通信
```

而且它必须是**唯一**的裁判。如果规则跑在玩家电脑上，任何人按 F12 改几行 JS 就能给自己发一手好牌。

所以需要一台能常驻运行 Node 的服务器。下文给出三条路，按推荐顺序排列。

| 方案 | 成本 | 朋友在哪都能玩 | 难度 |
|---|---|---|---|
| A. Render（推荐） | 免费 | ✅ | 点几下，不用命令行 |
| B. Docker（任意平台 / 自己的服务器） | 看平台 | ✅ | 中等 |
| C. 只在自己电脑上跑 | 免费 | ❌ 仅同一 WiFi | 最简单 |

---

## 二、方案 A：部署到 Render（免费）

Render 提供免费的 Node 运行环境，支持 WebSocket，并且能从仓库里的 `render.yaml` 自动读取配置——你不需要手填构建命令、启动命令、端口。

### 步骤 1：注册

1. 打开 <https://render.com>
2. 点右上角 **Get Started** → 选 **GitHub** 登录（用你 `tunbao666` 那个账号）
3. 授权 Render 读取你的仓库

> 如果注册过程中要求验证手机号或绑定银行卡：按提示做即可，免费套餐不会扣费，这一步是平台防滥用。

### 步骤 2：用 Blueprint 一键创建

1. 登录后进入 Dashboard，点右上角 **New +**
2. 选 **Blueprint**
3. 在仓库列表里找到 **Uno-game**，点 **Connect**
4. Blueprint 名称随便填（比如 `uno`），点 **Apply**

Render 会自动读到仓库里的 `render.yaml`，按里面的配置创建服务：

```yaml
runtime: node
plan: free
region: singapore        # 新加坡节点，国内延迟比美西低
buildCommand: npm install
startCommand: npm start
healthCheckPath: /healthz
```

### 步骤 3：等它构建

页面会显示构建日志，第一次大约 2–4 分钟。看到下面这行就算成功：

```
==> Your service is live 🎉
```

同时日志里应该出现：

```
UNO 已启动：http://localhost:10000
联机 WebSocket：ws://localhost:10000/ws
```

### 步骤 4：拿到你的链接

页面顶部会显示一个形如

```
https://uno-game-xxxx.onrender.com
```

的地址。**这就是发给朋友的链接**，手机、电脑都能直接打开，已经是 HTTPS。

### 步骤 5：自己先验一遍

1. 用电脑打开这个链接
2. 玩法选 **联机对战** → 填昵称 → **创建房间** → 记下 4 位房间码
3. 用手机（**关掉 WiFi 用流量**，这样才是真正的外网测试）打开同一个链接
4. 输入房间码加入 → 房主点开始 → 双方各 7 张牌，能互相看到对方出牌

如果手机用流量也能加入并出牌，说明部署完全成功。

## 三、免费套餐的三个真实限制（务必知道）

这些不是 bug，是所有免费平台的共同约束，提前知道能省掉一次困惑。

### 1. 闲置 15 分钟会休眠

没人访问时实例会被挂起，**下次打开需要等 30–60 秒冷启动**，期间页面会一直转圈。

对局进行中不会休眠（有活跃的 WebSocket 连接）。真正会遇到的场景是：你和朋友约好晚上玩，你先打开链接，卡了一分钟。

**应对**：开局前提前一分钟打开链接预热一次。想彻底解决就得升级付费套餐（约 $7/月）。

### 2. 重启会清空所有房间

房间和牌局全部存在内存里，实例重启（休眠唤醒、重新部署、平台维护）后房间码就失效了，所有人需要重新建房。

**这在一局游戏中途不会发生**（有连接就不休眠），但如果你在等待室里放很久，可能会掉。

### 3. 只有 512MB 内存

够几十个房间同时玩，服务端已加了 200 个房间的硬上限，超了会提示「服务器房间已满」。正常使用碰不到。

## 四、以后怎么更新代码

`render.yaml` 里设了 `autoDeploy: true`，所以在本地推送后，Render 会自动重新部署：

```bash
git push
```

约 2 分钟后新版本自动上线，不用做任何手动操作。

想看部署状态：Render 控制台 → 你的服务 → **Events** 标签。

## 五、方案 B：用 Docker 部署到别处

仓库根目录有 `Dockerfile`，任何支持容器的平台都能直接用（Railway、Zeabur、Fly.io、阿里云、腾讯云、自己的 VPS）。

```bash
# 本地构建并测试
docker build -t uno-game .
docker run -p 3000:3000 uno-game
```

然后打开 <http://localhost:3000>。

放到服务器上时，唯一需要注意的是**反向代理要转发 WebSocket**。以 Nginx 为例：

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;   # WebSocket 是长连接，别让它 60 秒就断
}
```

漏掉 `Upgrade` 和 `Connection` 这两行，现象是「页面能打开，但点创建房间一直转圈」——因为 WebSocket 握手被降级成了普通 HTTP。

## 六、方案 C：不部署，局域网内玩

如果你们就在同一个 WiFi 下（同一个家、同一个宿舍），不需要任何云服务：

1. 在你电脑上启动服务：

   ```bash
   cd D:\AI_workspace\web_game
   npm start
   ```

2. 查出你的局域网 IP：

   ```bash
   ipconfig
   ```

   找到「IPv4 地址」，形如 `192.168.1.5`。

3. 让朋友在浏览器打开 `http://192.168.1.5:3000`

**第一次运行 Windows 会弹防火墙提示，必须点「允许访问」**，否则别人连不上。如果已经点过「取消」，去「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」里手动勾上 Node.js。

## 七、排查清单

| 现象 | 原因 | 解决 |
|---|---|---|
| 打开链接一直转圈 | 实例在冷启动 | 等 30–60 秒，免费套餐正常现象 |
| 页面能开，点创建房间一直转 | WebSocket 被代理拦了 | 检查反向代理的 `Upgrade` / `Connection` 头 |
| 手机连不上局域网地址 | 防火墙拦了 3000 端口 | 允许 Node.js 通过防火墙 |
| 显示「房间不存在」 | 服务重启过，房间已清空 | 重新建房 |
| 显示「服务器房间已满」 | 达到 200 房间上限 | 极少发生，等几分钟空房被回收 |
| 显示「这局已经开始了」 | 对局中途有人想加入 | 设计如此，等这局结束（约 5–10 分钟） |
| 推送后网站没变 | 自动部署未触发 | Render 控制台手动点 **Manual Deploy** |

自检服务是否活着：

```bash
curl https://你的地址.onrender.com/healthz
# 期望：{"status":"ok","rooms":0,"uptime":123}
```

## 八、安全提醒

- 链接是公开的，任何人拿到都能建房。房间码是 4 位数字，理论上存在被陌生人撞码进入的可能——这是一款休闲游戏，影响仅限于「有人乱入你的房间」，介意的话可以打完就把房间关掉。
- 昵称做了转义和长度限制，不能注入 HTML。
- 服务端是唯一持有全部手牌的一方，客户端下发的数据里别人的手牌只有张数，摸牌堆只有剩余数量。改前端看不到任何隐藏信息。
